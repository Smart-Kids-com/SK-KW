# Collections editor — local delivery, 2026-10-15 (Asia/Kuwait)

## Preserved baseline

The existing `collections` records, title/description/image, URL handles, SEO, template, website/POS metadata and Active/Draft/Archived meanings are retained. Existing `collection_products` multiple membership and uniqueness remain the source of manual membership and independent manual positions. No product price, status, reservation or inventory balance is changed by collection actions. Existing Products, Orders, shared collapsible navigation/scroll fixes, and Theme documents/drafts remain in place. This work does not claim backend-wide completion.

## Working implementation

- English/LTR compact collection list with Arabic text direction, thumbnails, full titles, total-membership counts, condition summaries, publication status, updated dates, original useful sort/created/slug columns; server search/filter/stable ordering and pagination. Column visibility/order/reset and view preferences are browser-local and separate from catalog data.
- Explicit cross-page selection and owner-bound matching-result snapshots; Show all selected; metadata-only bulk editing of checked fields; Publish/Unpublish/Archive. Selection builds at most 500 IDs per call, durable SQL jobs process at most 20 collections per step, with per-item receipts/progress, conflict errors and failed-only retry. No in-memory background worker is required.
- Single deletion reviews title, logical membership count and Theme/navigation references. Bulk deletion has paginated name/count/reference review. Referenced collections are rejected rather than silently breaking current references. Soft deletion retains products, membership links and manual order; Deleted view restores as an unpublished Draft. Duplicate is a separate unpublished collection, copying rules, exclusions and order independently. Duplicate/create/move/delete operations have durable keyed replay support.
- Collection editor preserves original values, partial metadata updates and URL stability when renaming. Explicit Save/Cancel, unsaved-change warnings, reload-latest and revision conflicts protect against another window/Products membership writes. Preview reads saved data under admin authentication; it does not publish a collection. Public APIs expose only active, website-enabled, undeleted collections and active products.
- Grid/List, default four-column desktop grid, 3/4/5 density, images with `object-fit:contain`, full readable names, positions/selection/drag handles, server name/SKU search, multi-state filters/chips and paging. Product picker searches all pages; add/remove preserves other collections and uses unique membership keys, including concurrent/retried additions from Products. Removing from an Automated collection creates a persistent exclusion; exclusions have a paginated management dialog.
- Admin display sort is a saved browser preference. Published sort requires metadata Save. Title A–Z/Z–A, effective current price, product-created Newest/Oldest and independent manual ordering are implemented. Position moves and drag operate on the complete collection, across pages, including manual pinning within Automated results. Existing manual positions are not reset when switching sorts. Membership mutations accept at most 500 IDs per request; list/item pages remain bounded.
- Automated conditions support Title, Category, Type, Vendor, Tag, actual Status, effective Price and Inventory **available after reservations**. Server validation restricts property/operator/value types; All/Any, editing/removal and unsaved count/result preview are implemented. No raw user SQL is accepted.
- Automated membership is persisted in `collection_automated_products`. Database triggers evaluate the changed product on relevant product writes; saving changed rules evaluates that collection once. Ordinary page reads use indexed links/counts rather than rebuilding the product catalog. Updates are synchronous in the database transaction; no polling or ephemeral server memory job is needed. Exclusions remain separate and survive rule/product changes.
- Existing Theme image library/upload API is reused (PNG/JPEG/WebP, up to 2 MiB, original bytes/dimensions retained in DB-backed media). No new paid service or video storage.
- Storefront list/navigation fetch every page rather than truncating at 80/120 groups. Saved image/title/description/order reach collection pages and related current/legacy Theme sections. Unpublishing does not fall back to unrelated products in legacy featured-collection sections. Affected collection/Theme price displays use the authoritative effective-price rule; pricing and inventory mutation logic are unchanged. Theme editor gets an authenticated all-status catalog, while public rendering stays publication-filtered.

## New migration — temporary database only

`db/collections-editor-migration.js` exports `migrateCollectionsEditor(db)`. It adds `kind='manual'`, `match_mode='all'`, `rules_json='[]'`, revision and soft-delete fields without rewriting existing collection content or manual memberships. It adds automated-membership/exclusion tables, durable selection/job/receipt/operation tables, indexes, membership revision triggers and automated-membership triggers. DDL is applied as an atomic batch; a one-time map initialization applies only when the new map table is first created. Existing automated data, if upgrading a local development copy, is mapped once from saved rules. Existing collections remain Manual by default.

No production database was read or migrated. Future deployment needs this **new** migration on the confirmed store DB and the previously prepared Theme/media schema; it does not require inventory settlement or replaying prior migrations. The new admin endpoints return schema-readiness errors until the collection migration exists. Legacy public handlers remain available on an unmigrated baseline, but the new editor requires the migration.

## Verification evidence and limits

Eight dedicated Collections cases passed over the full run plus focused follow-ups, on isolated temporary store/auth DBs, with external traffic/mail/Meta blocked. The existing `Add to collection:` Products case was reused and passed after adapting its fixture/private read path for the new editor. Other successful pricing/order/CSV/history suites were not rerun.

Verified: migration preserves existing collection fields, links and inventory snapshot; 133+ collections/237 products; name/slug search beyond first page; exact counts and stable sort; 70-product memberships; concurrent/repeated additions and another membership retained; Arabic save, original media upload and reload; unchanged URL; stale-window rejection; unpublished independent duplicate and replay; complete-order moves across pages; all/any and supported typed conditions; immediate product-driven membership and exclusions; public visibility; 603-result selection built in 500-ID pages; 20-item jobs, receipts and failed-only retry; reference-blocked/restorable deletion; legacy Best selling remains stored but publicly identifies the honest manual fallback; private Theme catalog includes Draft without publishing it.

Browser verification covered list/editor/reviews, 30-item multi-page picker, column preferences, Grid/List persistence, server state filters, native keyboard menu and modal Escape, unsaved Cancel rejection, stale save/reload, actual drag/position changes, normal mouse-wheel scrolling, 390px layout/horizontal table and touch swipe. Storefront browser checks covered >100 public collection cards and navigation links, original group image/description, correct price/order, current and legacy Theme sources and unpublish behavior.

Physical devices/real touchpad and production-scale latency/load were not tested. The fixture is synthetic; no real messages, mail, Meta, checkout or payment was sent. Best selling is unavailable because completed net sold-piece/return data is insufficient; Most relevant has no defined relevance model. Independent Compare at price, Weight, Variants, Unlisted/Suspended states and real sales channels are absent from the current model and are not presented as functioning features. The legacy Best selling value and POS flag are preserved, with honest limitations.
